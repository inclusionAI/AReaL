# 从相关工作到可验证实验

这是建议的实验设计，不是已取得结果。项目既有训练约束和数据口径以 [PLAN.md](../../PLAN.md) 为准；论文依据见 [证据矩阵](EVIDENCE.md)。

## 两个递进问题

**H1：动态配置是否值得做？** 在同一任务分布、模型及训练语义下，不同时间段的优选配置确实变化，而且收益足以覆盖 profiling、搜索、同步、转换和恢复。

**H2：为什么需要修订？** 强在线校准／重规划仍存在可重复的决策损失；修改性能模型结构或规划算法后，独立测量确认额外收益大于修订成本。

H1 不成立时，不以“负载 dynamic”为由继续主张动态优化有效。H2 不成立时，结果应支持普通自适应方法，或将 LLM 工作限定为离线设计辅助。

## 最小基线与消融

所有方法共享可行动作、观测、学习约束和执行机制。普通方法也获得相同历史测量，允许动态决策。

| 对照                         | 固定与变化项                                                       | 回答的问题                                            |
| ---------------------------- | ------------------------------------------------------------------ | ----------------------------------------------------- |
| B0：验证集选出的最佳固定配置 | 整段执行同一配置；选择过程不接触最终测试                           | 复杂控制相比合理静态配置是否值得？                    |
| B1：固定模型＋固定 planner   | 模型结构／参数及算法固定；输入实时负载，重新选配置                 | 仅随负载重新决策能解决多少问题？                      |
| B2：在线校准＋固定 planner   | 更新速率／回归参数；允许偏差触发 profiling／重规划、收益阈值与冷却 | 对 DynaRL／RLinf／Nereus 类普通适应机制是否仍有增益？ |
| B3：模型修订                 | 从 B2 出发，只允许改变 Basic 性能模型                              | 结构性建模不足是否影响实际决策？                      |
| B4：规划算法修订             | 与 B2 相同的模型／校准规则，只改变搜索或决策代码                   | 固定计算预算下，算法修订是否有效？                    |
| B5：联合修订                 | 同时允许 B3、B4，保持相同验收条件                                  | 联合收益是否超出单项修订？                            |
| R：冻结 Expert 参考          | 不含 optimizer；给相同候选计划评分                                 | 诊断 Basic 的预测和计划差距；自身精度须经实测确认。   |
| O：受限离线上界              | 小规模测量／枚举配置；可另报知道未来的理想策略                     | 区分机会空间、预测损失与搜索损失；不是可部署基线。    |

B1／B2 的 planner 需认真调优，至少与相同搜索预算下的枚举、小规模动态规划或其他合适搜索比较。不能故意使用弱模型或低效算法制造修订优势。 若主张 LLM
的结构修订优于传统适应，还应增加非 LLM 的残差学习／模型重选对照，共享观测数据和评估预算，分离“模型容量增加”与“代码修订”的作用。

按本轮分层，直接系统优先比较 Libra、DynaRL、RLinf；Level 1 的 Nereus 保留为强在线校准／转换收益参照。 长时程角色切换参考
QwenGyre，PD 配置参考 PEARL。优先复用作者实现；若只移植机制，写明“受该方法启发的基线”，不称完整复现。 TideRL 的 batch 弹性、ReFlow 的
experience replay 及 QwenGyre 的轨迹处理分别做允许相应语义变化的实验。

LLMZero 调整训练超参数并可重置优化器状态，适合比较反馈驱动的训练策略搜索；不能直接充当保持训练语义的 planner 修订基线。 Autopoiesis／ADRD
提供代码演化及模型／策略共同改进的机制参照；移植到 RL 后需重新验证，不能照搬其跨领域收益数字。

## 现有数据与最小补证

| 当前材料                                    | 能支持什么                               | 还缺什么                                                                                                |
| ------------------------------------------- | ---------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| 公司端九条 Tau2、988 个完整 step 的转述摘要 | 负载和阶段耗时存在变化、部分模型校准线索 | 本地未读原始日志；v1／v2 语义核对；同 workload 跨配置。只有一种 rollout 布局，不能用 trial 总耗时排名。 |
| R10 真机 trial 与固定到达回放               | 执行链与原配置的条件诊断                 | 改变配置后的到达、队列、质量与端到端净收益。                                                            |
| 当前 Expert 模型及 CPU 回归                 | 接口、记账和受测路径的正确性             | 跨配置实测精度，尤其 rollout、packing、权重同步与转换。                                                 |

最小补证按以下顺序进行：

1. **分解一条真实运行时间线。** 记录推理、工具／sandbox 等待、可训练 group 到达、训练阶段、权重版本、队列及持有的 GPU
   allocation。区分内生轨迹长度变化、外部请求到达变化与资源供给变化。
1. **同 workload 测少量代表配置。** 先覆盖当前运行时确实支持的 actor／rollout
   配置；固定任务、逻辑输入及训练设置，重复测量并控制顺序效应，观察瓶颈与配置排名是否变化。
1. **测真实转换。** 包括 drain、checkpoint、进程启动、状态恢复／重分片、同步和失败回退。用持续收益的回收时间判断是否值得切换，不能继续把
   60s／120s 情景常数当实测。
1. **先跑 B0–B2，再跑修订。** 先验证收益空间及普通适应能力，再选择真实残差明显、可解释的场景。平稳负载和短暂噪声也应保留，检验无谓切换和负收益。

纯性能实验可用固定策略和任务隔离资源配置的作用；最终仍须端到端学习实验。跨配置模拟必须重新计算排队与到达，固定原到达的回放只回答条件问题。

## 验收与报告口径

- **成本／效率：** allocated GPU-hours、完成时间、有效训练数据量分别报告；CPU／环境、LLM API、搜索和 profiling
  成本另列。释放显存、转作 rollout 与归还 allocation 分开统计；货币费用注明价格与计费粒度。
- **学习约束：** 固定模型、global batch、PPO／GRPO 设置、数据复用规则；报告 held-out 质量、staleness
  分布、丢弃／截断量。允许变化的设置另作实验。
- **模型价值：** 除阶段误差、覆盖率外，报告配置排序、选错计划的实测损失；模型更准不自动代表计划更好。
- **修订价值：** 与 B2 比较累计净收益、恢复到有效策略所需时间、评估次数、接受率和回退；相同 LLM／评估预算，区分冷启动和已有经验的起点。
- **时间尺度：** 快速反馈控制与较慢的代码修订分开。短暂突发先由运行时控制处理；比较修订耗时和负载持续时间，不假设 LLM 能即时响应。
- **验证独立性：** Basic 不能改验收器、评分标签或最终留出集。Expert 每组实验冻结，不用其输出冒充实测；最终验证仍依赖独立运行。
- **数据划分：** 保留现有校准／验证／最终留出划分，增加未见配置或 workload 的验证。在线过程先预测与决策，再观察并更新，禁止使用未来数据。最后 200 个保留
  step 不为本次调研消耗。

目前没有充分证据确认 H1 或 H2。本轮交付完成的是文献定位和可执行的证据要求。
